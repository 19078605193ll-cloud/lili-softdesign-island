# AI 回答长时间等待排查（2026-10-02）

## 2026-10-03：教学模型自动切换

当前本地教学配置为：

```dotenv
AI_TUTOR_MODEL=gpt-5.4-mini
AI_TUTOR_FALLBACK_MODELS=["qwen3.8-flash","gemini-3.8-flash"]
AI_TUTOR_REASONING_EFFORT=low
AI_TUTOR_TIMEOUT_SECONDS=30
```

导师对话、变式题生成和复核共用这条调用链，以及原有 DMX 地址和密钥。
每次调用从主模型开始，失败后按配置顺序切换，重复模型去重。
每个模型只调用一次，SDK 自动重试关闭，异步截止时间限制单次请求为 30 秒。
三个模型全部失败后任务直接失败，用户可通过页面“重试”发起新请求。
之前的教学任务自动重试一次机制不再用于模型调用失败。

超时、网络故障、408/429/5xx、明确模型不可用错误以及空、超长、截断或
不合法 JSON 响应会触发切换。账户鉴权、余额不足、通用参数错误不切换；
模型不可用只按明确错误码识别，不依据供应商自由文本猜测。
题目复核不合格仍走原有最多两轮生成与复核流程。

一次调用链的模型等待最多约 90 秒，变式题最多四条调用链，累计约 360 秒；
不含排队、数据库处理和进程调度时间。教学任务现有 Celery 执行上限为
600 秒，数据库租约为 660 秒。Redis 在 360 秒可能重新投递尚未确认的消息，
worker 的 running 状态及租约检查会阻止重复执行和重复保存。
如果提高超时或增加模型数量，必须同时评估这些任务时限。

内部调用可通过 metadata 返回成功模型，变式题 model 字段记录实际生成模型。
API 响应和数据库结构未新增字段。日志 learning_ai_attempt_failed 和
learning_ai_usage 包含 job_id、stage、model、attempt、耗时、结果；失败日志
包含异常类型、HTTP 状态和 next_model。日志不写密钥、题目、会话或供应商错误正文。

验证记录：三个指定模型分别接受 reasoning_effort=low 的短文本和 JSON 请求，
共六次请求成功；模拟主模型超时后 Qwen 返回正确 JSON，模拟前两个模型超时后
Gemini 返回正确 JSON。接口接受参数不等于能观测供应商内部的实际推理预算。
隔离测试覆盖调用顺序、截止时间、错误分类、取消、输出校验及任务失败后的手动重试。

最终验收：相关后端与任务故障测试 47 项通过；Chromium、WebKit 的教学完整流程
均通过，浏览器 fixture 仅替换供应商传输，实际执行三级调用链。整套浏览器测试
21/22 通过，现有连续答对庆祝测试出现一次偶发失败，单独复跑通过，未修改该功能。
前端与本地镜像构建成功，API、worker、dispatcher 已重新创建；live/ready 检查通过，
新 worker 读取到上述配置并完成一次真实主模型 JSON 请求。

回退时将 AI_TUTOR_FALLBACK_MODELS 设为 []；AI_TUTOR_REASONING_EFFORT 留空
会恢复供应商默认推理设置。AI_TUTOR_TIMEOUT_SECONDS 可独立恢复为 120；
AI_TIMEOUT_SECONDS 继续用于其他 AI 功能。修改后重新创建容器才能加载环境变量。

以下保留 2026-10-02 的故障记录，当时的超时和重试配置已被上述行为替代。

## 原因与证据

本机 `http://127.0.0.1:8000/h5/` 最近三条失败教学任务的错误均为
`APITimeoutError`。Worker 已领取任务，每次模型调用约 120 秒后超时，
自动重试一次，总等待约四分钟。Celery 的 `Task succeeded` 仅表示执行函数
正常返回；业务失败已写入 PostgreSQL `jobs`，不能据此判断模型回答成功。

在相同 worker 容器、供应商 URL 和密钥下做最短请求对照：

| 请求 | 结果 |
| --- | --- |
| `/models` | HTTP 200，1.06 秒 |
| `gpt-5.6-luna`，非流式 | 25 秒探测超时；原业务请求 120 秒超时 |
| `gpt-5.6-luna`，流式 | 35 秒探测超时 |
| `gpt-5.4-mini` | HTTP 200，2.28 秒，返回 OK |
| `gpt-4.1-mini` | HTTP 200，3.12 秒，返回 OK |

故障定位到 DMXAPI 的 `gpt-5.6-luna` 调用路径。无法仅凭这些数据区分
供应商内部排队和其上游故障，但不是普遍的容器断网、密钥失效或队列未执行。

## 再次出现时

先检查 `jobs.error_code` 和 worker 日志，区分排队、模型超时、鉴权及限流。
使用相同容器和最短消息对照当前模型与已知可用模型，避免只增加等待时间。
调整 `.env` 后执行：

```powershell
docker compose -f compose.local.yml -p softdesign-island-app up -d --force-recreate api worker dispatcher
```

仅执行 `restart` 不会加载新环境变量。模型恢复后可在页面点击“重试”。
